ℹ️
Why two separate Supabase projects?
OMS and TMS are independently deployed systems. Keeping them in separate Supabase projects enforces hard boundaries — a bug in OMS can never corrupt TMS tables, and each system can be scaled, backed up, or migrated independently. The Middleware is the only layer that holds credentials for both, and it applies field-level mapping and validation before any data crosses the boundary.

How API Keys Work in Production
In a fully deployed middleware (e.g. Node.js on Railway), OMS and TMS would authenticate every request with a bearer token. The middleware validates the key, checks permissions, applies rate limits, and logs every call. The Supabase credentials never leave the middleware — OMS and TMS only see middleware endpoints, not the underlying databases.
